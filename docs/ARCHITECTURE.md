# Aspira architecture

Aspira is a local-first personal-agent workspace. The browser interface runs on Vite at `127.0.0.1:5173`; an Express service at `127.0.0.1:3001` handles provider CLI calls and local tools. The API binds to loopback and Vite proxies `/api` requests to it.

## Conversation and providers

`src/App.tsx` owns the selected providers, current conversation, saved context, and voice state. If Aspira verifies a signed-in provider at startup, it selects that provider for the first conversation; the user can change the selection. `src/plugins/models/synergyEngine.ts` sends each turn to the selected providers through `/api/dispatch` and renders their separate responses. Only the lead model receives the tool protocol and may run local actions; other selected models receive the conversation and return their own responses. The app does not invent model output, agreement scores, token rates, or latency estimates. If no provider is selected, the local action parser can still handle a supported request; other prompts explain that a provider is needed.

The browser requests newline-delimited JSON from `/api/dispatch`; clients without that Accept header retain the ordinary JSON response contract. Activity events report provider waits, streamed Codex text, action starts, and actual action receipts, followed by one terminal result. The browser renders the user's turn immediately and can show each model's finished reply before the other providers finish. Cancellation preserves received replies and action receipts and names started actions whose completion was not reported. Follow-up model context includes the latest six recorded action outputs per recent turn, with each excerpt capped at 2,000 characters and explicitly marked when shortened, so stopping a reply does not erase evidence of work that already ran. A shared execution guard prevents overlapping chat, playbook, app-handoff, and reviewed-edit requests from overwriting the current task state.

`conversationRecovery.ts` synchronously checkpoints each conversational activity event in tab-scoped session storage, together with the current conversation's completed turns. A received final result is checkpointed before React updates history; its checkpoint is acknowledged only after the local-storage history write succeeds. Initial loading merges unfinished checkpoints as interrupted turns without re-executing actions, preserves final answers that arrived before reload, and deduplicates by conversation and turn. Before-unload and page-hide handlers preserve an interruption record before aborting the provider request, preventing the navigation disconnect from being misclassified as an agent-service failure. Drafts use a separate per-conversation session-storage map, including a new-chat slot. This is reload recovery for conversational turns, not a server-side background job queue or cross-tab sync. Older readable chat turns are normalized with safe empty arrays, while malformed turns are skipped without discarding their valid siblings.

The server detects whether supported CLI programs are installed. It checks Codex sign-in status through its local status command; it does not read credential files or return account details. Claude Code is offered as an official app handoff, not used to route a Claude.ai subscription through Aspira. Antigravity and Grok show CLI availability in Settings; successful replies identify their CLI as the response path:

- Google: Antigravity CLI (`agy`), sandbox and plan mode.
- Anthropic: API key for in-Aspira inference, or open Claude Code for subscription use.
- OpenAI: Codex CLI app-server (`codex`), persistent read-only thread per Aspira conversation with structured Aspira tools.
- xAI: Grok Build CLI (`grok`), plan mode.

The provider's CLI support, account state, plan, and terms determine whether a request succeeds. Aspira verifies only the CLI status information exposed by the provider and does not inspect or claim the account's plan tier. Optional API-compatible endpoints and explicit API keys are separate settings. A desktop app being installed does not connect its model to Aspira.

Antigravity and Grok subscription requests use fresh private temporary working directories; the prompt is passed without putting it in command-line arguments. Antigravity uses its headless sandbox and plan mode with slash-command expansion disabled. Grok runs one headless turn in plan mode. Codex is a separate path: Aspira starts or resumes a persistent app-server thread in the workspace with a read-only sandbox and registers a structured `aspira` tool namespace. Aspira handles those tool calls in its own process, applies user-intent checks, and declines unsupported provider approval requests. Thread IDs are stored in `server/data/codex-provider-sessions.json`; the signed-in Codex app-server keeps its conversation data according to Codex's own local settings. Claude subscription chat remains in Claude Code; an explicit Anthropic API key is required for Claude replies inside Aspira. API-key, token, secret, password, and credential environment variables are removed from subscription CLI environments; direct API requests use only keys configured in Aspira. The composer can cancel a provider request; the server forwards the abort to the provider CLI, app-server, or direct HTTP request. A local action that has already started may still finish.

## Conversation-first interface

The app has one conversation surface and a sidebar containing recent threads, agents, and settings. Agent selection lives in the composer and is remembered in browser local storage. Provider availability and actual selected participants remain separate. The first selected provider retains the existing bounded tool role; additional providers receive the same request and return their own responses.

A response can open in `WorkspaceSheets` as an adjacent reading pane at 1440px or wider, and as a modal below that breakpoint. The preview shows received Markdown, not a new generated artifact or filesystem view. Ask another agent creates an explicit review/continuation draft, shows the answer being shared (capped at 16,000 characters with an excerpt notice), and waits for Send. An unavailable provider can be opened in its official app or site; the server copies that turn's prompt, may paste it into the app, and never submits it. The visible message uses a concise review label; the provider receives the full bounded request plus existing conversation and saved context. No routing, role assignment, or persistent background execution is implied.

Needs you derives pending/conflicting edit proposals, interrupted/stopped turns, failed/blocked actions, and unavailable providers from saved conversations, replacing the active conversation's stale saved snapshot before grouping. Proposal IDs and turn IDs prevent duplicate notices. Dismissed historical notice IDs are stored separately in browser local storage, capped at 300; pending review proposals cannot be dismissed through this control. Selecting a notice switches to its conversation and scrolls to the relevant turn, and is disabled during an active request.

Voice remains in the same conversation through a small composer panel. Opening it does not request the microphone. Recording, Stop & send, cancellation, preparation progress, and playback have distinct controls. A recording generation token prevents a cancelled recording or transcription from submitting later. On small screens the shell follows the visual viewport height to keep input reachable when usable screen space changes. No local voice service is configured.

## Local action boundary

`server/index.js` maps explicit requests to a bounded tool registry. The selected lead model can request tools through the legacy exact-JSON protocol; Codex receives the same registry as structured app-server tools. In both cases the server checks that the user asked for the corresponding action, maps it to a registered implementation, and returns the actual result to the model. A turn is limited to three tool calls. Available model tools are Git status; workspace listing, text search, file reads, new-file creation, and reviewed edit proposals; basic system status; allowlisted app launch; URL opening; public web search; and explicitly requested memory saves. Commands run with argument arrays and an exact read-only allowlist, not a shell.

Workspace reads are limited to text/source extensions and exclude hidden, generated, dependency, local-data, and likely credential paths. Path checks include resolved symlink targets. File creation is limited to a new file, at most 200 KB, under an existing workspace directory. Aspira does not expose arbitrary shell execution, unreviewed overwrites, or scheduled routines. The listed routines remain user-triggered local playbooks. The frontend does not expose the legacy source-browser, Git-diff, terminal, or telemetry views; bounded tools remain available through explicit conversation requests. Search is bounded by file count and result count.

`workspace.propose_edit` prepares one exact, unique text replacement in an existing UTF-8 text/source file of at most 200 KB. It returns a bounded unified diff generated with jsdiff, before/after SHA-256 revisions, and a proposal ID. It does not write the file. Only the app's explicit Apply control calls `POST /api/file-edits/:id/apply`; Apply rechecks both the reviewed proposal and current file revision before a temporary-file rename. Undo requires the file to match the applied revision; later work blocks it. Discard never changes the source file. These operations are unavailable to the model tool protocol. Optimistic revision checks protect against ordinary stale edits; they are not a filesystem transaction against arbitrary simultaneous external writers.

`server/fileEdits.js` persists immutable before/after contents and operation state in `server/data/edit-proposals/` (directory mode 0700, records 0600, excluded from Git and workspace tools). Transitional Apply/Undo states reconcile with the actual file hash after restart. `GET /api/file-edits/:id` returns the current proposal and latest operation receipt, letting the browser recover an outcome after a lost response. Stable receipt IDs prevent duplicates on retries. Proposal state and actual operation receipts also survive browser conversation persistence and reach subsequent model context; a prepared proposal is never labeled as an applied write. Credential-like strings are redacted in the displayed diff using the existing redactor, without altering the exact stored replacement.

File reads are capped at 1 MB on disk. Each numbered page returns at most 6,000 content characters and defaults to 80 lines (maxLines is capped at 200); long lines resume with a line-and-column cursor so no characters are skipped. SHA-256 revision checks prevent silently continuing into a changed file. The immediate tool-result context allows up to 10,000 characters so each complete bounded file page reaches the responding model. File-page metadata is retained separately from the 2,000-character history excerpt. Read-only conversational follow-ups use the last successful file receipt and cannot switch to another path or authorize other tools; an explicit fresh read starts at the beginning. The latest file receipt exposes a next-page control. The server reports action-limit exhaustion instead of returning a raw tool-request JSON object as a reply.

## Local data and voice

Memories and user-edited playbooks are stored in `server/data/` on this Mac and excluded from Git. Memories are saved only after an explicit request; Aspira does not automatically extract them from conversation. Up to 24 conversations are stored in browser local storage, where the user can search, reopen, and delete them; this data is not synced or encrypted. Provider prompts include the user's prompt, a small recent conversation window, and up to eight saved memory notes. Results from a requested tool call are sent to the same provider for the follow-up response.

Voice input and spoken replies run in a browser worker with Kokoro-82M and Whisper Tiny through Transformers.js. The browser downloads model files from Hugging Face on first use and caches them. Audio inference does not call a local or remote speech service; only the recognized transcript is sent to the selected model when the user submits a voice message. Microphone capture begins only after the user presses the voice control. The optional passphrase is a browser convenience lock, not device authentication.

## Main code paths

- `src/App.tsx`: top-level state, chat flow and local conversation-history persistence, provider selection, voice controls, and lock.
- `src/components/ConversationHistoryPanel.tsx`: searchable local chat history and thread controls.
- `src/plugins/models/conversationHistory.ts`: browser-local conversation validation, titles, dates, and retention cap.
- `src/components/ConversationWorkspace.tsx`: continuous conversation, real progress, action receipts, and response controls.
- `src/components/WorkspaceSheets.tsx`: contextual result preview and attention drawer, with focus and keyboard handling.
- `src/plugins/models/workspaceAttention.ts`: deduplicated notices from recorded conversation outcomes.
- `src/workspace.css`: conversation-first shell, responsive composer, and shared visual tokens.
- `src/components/FileEditProposalCard.tsx`: inline diff review, Apply/Discard/Undo, and status recovery.
- `src/plugins/models/fileEditProposals.ts`: proposal validation and deduplicated operation receipts.
- `src/components/PlugAndPlayVaultModal.tsx`: provider, endpoint, built-in voice, and passphrase settings.
- `src/audio/speech.worker.ts`: browser worker for speech generation and transcription.
- `src/audio/soundEngine.ts`: voice model status, browser audio playback, and microphone audio preparation.
- `src/plugins/models/manifest.ts`: provider and conversation data types.
- `src/plugins/models/synergyEngine.ts`: provider dispatch and truthful result aggregation.
- `server/index.js`: local API, CLI invocation, local actions, memory, routines, file graph, and Git diff.
- `server/codexAppServer.js`: Codex app-server lifecycle, resumable conversation threads, structured tool calls, and text streaming.
- `server/fileEdits.js`: persistent exact edit proposals and version-checked Apply/Undo.
- `server/workspacePaths.js`: shared workspace path and text-file boundaries.

Run `npm run dev` for local development, `npm run build` for the production bundle, and `npx tsc --noEmit` for the TypeScript check. Voice model files download automatically when voice is first used.
